# Framing experiment prompts (retail)

Used with `run_eval.sh --with-policy`. `agent.py` appends the verbatim τ²-bench
retail policy to each file in a `<policy>` block, so every condition carries the
same rules and the conditions differ only in framing.

## Trimming rule

Each prompt keeps its condition's framing and procedure but restates no specific
policy rule (order statuses, payment-method rules, gift-card balance, one-shot
tools, and so on). It may refer to "the policy below" in its own voice. The policy
is the only source of rules.

| File | Derived from | Kept |
|---|---|---|
| `condition-a.md` | `../condition-a-unstructured.md` | Role sentence only, the minimal practitioner baseline |
| `condition-b.md` | `../condition-b-risen.md` | RISEN structure and step sequence, with rule content replaced by references to the policy |
| `condition-c.md` | `character-sheets/retail-ledger-character-sheet.md` | Translation template from PLAN.md applied to the ledger sheet: artifact, protects, remembers, resists, blind spot |
| `condition-cv2.md` | `character-sheets/retail-ledger-character-sheet.md` | Condition C plus the ledger sheet's mood-grid triggers |

"Product recommendations" became "opinions" in B and C, because the k=1 GPT-4o
runs showed the old wording being over-applied to catalog lookups.

## Artifact

C and C-v2 use the **ledger**, not the order kiosk used by the paraphrase-only prompts
in `../`. A kiosk is a specialized interface in front of the record, while the benchmark
assumes a chat conversation. See "Artifact choice: from kiosk to ledger" in PLAN.md.
